# R5.1b Delegatus and YYLO, read closely

Read via the GitHub API on 2026-10-30 (default branch HEAD). This was the "Revisit if" check in [D0002](../decisions/D0002-build-foreman.md).

**Result: adopt neither, keep building foreman.**
- **Delegatus** is a large local web platform (Next.js, tmux session hosting, Telegram). Its state lives in a per-user directory, its tasks are coarse, and it has no claim protocol for parallel worktrees.
- **YYLO** is closest in spirit: leases, receipts, a risk policy and a one-at-a-time merge. But it is several hundred KB of Python tied to its own ledger, controller layout and agent runner, with JSON+flock storage and no MCP task layer.

Both are MIT. They are design references, and Delegatus's prompts are good source text.

## What to borrow, and when

| Idea | From | Lands in |
|---|---|---|
| Verdict `pass \| fail \| needs_decision`. `needs_decision` carries a question, options and a recommendation, not findings | Delegatus | M6 verifier |
| Label each claim CONFIRMED / WRONG / UNCONFIRMED with evidence. Any WRONG → fail; any UNCONFIRMED → needs_decision; all CONFIRMED → pass. Foreman adds the per-check array (`check`, label, evidence, command, exit code) that Delegatus lacks | Delegatus | M6 |
| A finding must name the contract it breaks (the acceptance check id), the paths, the evidence, the failure condition and the acceptance condition. Out-of-scope remarks only count in `rejection_counters`. Reviews must report truncation honestly | YYLO | M6 |
| Severity comes from policy (impact category → severity; only high and critical block), never from the model | YYLO | M6 |
| A finding failing on base as well as head is pre-existing: a note, not a blocker | Delegatus | M6 |
| Receipts addressed by content: canonical JSON + sha256, referenced as `{path, sha256}`, re-hashed on read, size-bounded, no transcripts. Bound to candidate sha and tree, base sha and policy hash. Merge recomputes eligibility from live git | YYLO | M4/M6 (D0004 check records) |
| Risk tier from changed paths and flags, failing closed: workflows, auth, migrations and lockfiles → high; docs only → low; ambiguous → high. Required reviews and the full suite follow from the tier | YYLO | M6 (suggests `risk`, a person confirms) |
| A lease timeout alone never hands a task over; it takes proven worker death (PID + start time), a handoff or a revoke | YYLO | M6 (see D0006) |
| Auto-merge only when checks are "settled and green": required checks present, ≥3 min since the head appeared, the set of checks stable across two reads, nothing red even if optional, no checks means blocked. One merge slot per repo; compare-and-swap on the target ref; moved target → recheck | both | M6 merge queue (D0004) |
| Budgets on fix loops (`advance` / `stop-after-fix` / `park`), counted from the event log; "last fix not re-reviewed" shown wherever the task is | Delegatus | M6 |
| Read-only verifier launch: `claude -p --permission-mode plan --disallowedTools Edit,Write,NotebookEdit,AskUserQuestion,ExitPlanMode`, never skipping permissions. Afterwards check that HEAD and the worktree are unchanged. Pure judgment calls: `--tools "" --strict-mcp-config --setting-sources "" --no-session-persistence --max-turns N --json-schema …` plus a watchdog that kills the process group | Delegatus + YYLO | M6 launch adapter |
| Writes guarded by expected head and revision (compare-and-swap on the task) | Delegatus | M6, when verdicts reference a head sha |
